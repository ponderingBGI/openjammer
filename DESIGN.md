# Design System: OpenJammer

> The retired system was **"The Living Sketchbook"** — Caveat in functional UI, cream
> paper, 2px ink outlines, hard blur-free offset shadows. It is gone, deliberately and
> completely. Nothing in this document is a variation on it; see
> [PRODUCT.md § Anti-references](PRODUCT.md#anti-references) for why.

## 1. Overview: A Real Instrument

**Creative North Star: "A Real Instrument."**

OpenJammer should read the way a well-made piece of hardware reads on a table in front of
a room: quiet where it is quiet, loud exactly where the signal is. The canvas is a calm
warm neutral (`--bg-canvas`) under a faint dot grid. Nodes are white cards
(`--bg-node`) with a single hairline edge (`--border-subtle`), soft layered depth
(`--shadow-raised` / `--shadow-overlay`), and ports that are **recessed socket wells
sunk into the body of the card** — the shape a patchbay already taught the hand. Colour
is spent only on signal, state and selection, so the loudest thing on screen is always
the patch.

The system is still **crafted, immediate, and deep** — the same three words as before,
carried by different means. The whimsy that used to live in a handwritten line now lives
in **motion, physics, and sound-reactive light**, which is where a performer actually
feels it: a button compresses under the thumb, a knob resists and springs, a key lights
solid accent while it is held, and a cable *thickens and glows in proportion to the audio
actually passing through it*.

Four principles hold it together. They come from the approved handoff and they are
absolute:

1. **Calm ground, loud signal.** Quiet warm-neutral surfaces. Saturated colour is
   reserved for signal, state and selection — nothing else earns it.
2. **Everything has weight.** Buttons compress, knobs resist, toggles spring. One spring
   curve everywhere (`--motion-spring`), one fast curve for colour (`--motion-fast`).
3. **Sound is visible.** Only elements carrying live audio may glow or pulse — cables and
   meters. **Nothing else glows, ever.**
4. **Legible always.** UI text ≥13px, AA contrast minimum, mono for exact values. No
   decorative type in functional UI.

Those four sit on top of the product's four disciplines, unchanged. **Less, but better:**
a node is read at a glance, mid-performance, in peripheral vision. **Instant by default:**
a felt delay between gesture and sound is a design failure before it is a technical one.
**Honest interfaces:** metering that doesn't lie, the honest `~15–25ms` browser tier never
dressed up as sub-5ms, a transport glyph that waits for the engine before it claims to be
rolling. **Coherence over consistency:** the card grammar is shared, not stamped — force
the same care everywhere, leave room for what each node needs.

**Key characteristics**

- Warm-neutral dot-grid canvas; nodes are white cards with **1px** hairline borders and
  soft layered shadows. No 2px ink, no hard offset shadow anywhere.
- **Outfit** is the UI voice at every size; **JetBrains Mono** means "exact." No display
  face in functional UI.
- Ports are **18px recessed socket wells inside the node body**, in labelled rows —
  inputs left, outputs right, first row of the body. Ports never glow.
- Port colour is meaning: **audio = teal, control = grey, universal = violet.**
- Radii 6 / 10 / 14 / 20 / pill 99; the node card is 14px.
- Exactly **two themes**, Light (default) and Dark, as pure value swaps of the same 53
  semantic tokens.
- One focus ring (`--focus-ring`), one blanket reduced-motion rule, two exemptions.

## 2. Colors

Two themes, 53 semantic tokens each, identical key sets
(`packages/oj-tokens/tokens/themes/{light,dark}.json`). Every value below is the shipped
token — a component that names a literal colour is a bug, and that is now enforced on the
source as well as the stylesheets (`Arrangement/__tests__/tokenLiteralGate.test.ts`).

The count is 53 again after passing through 54: `accentTwoInk` was added (the readable ink
of the second accent, minted so the piano-roll note could clear 3:1 at its velocity floor),
and `universalPort` was removed — it was declared in both themes and read by **nothing**,
while `AGENTS.md`'s port law pointed readers at it instead of at `--universal-connection`,
the token that actually paints the socket and the cable. A dormant token is a lie about
what the system is (code-value #8).

### Surfaces

- **`--bg-canvas` / `--bg-primary`** (`#F4F3F0` / `#161510`): the stage. Warm neutral,
  never grey, printed with a faint dot grid.
- **`--bg-node`** (`#FFFFFF` / `#201F19`): the card. Node bodies, menus, modals, the
  transport pill, the raised segment of a segmented control.
- **`--bg-node-header` / `--bg-secondary`** (`#FAF9F6` / `#242219`): the topbar, node
  headers, timeline chrome — one step off the card.
- **`--bg-tertiary`** (`#ECEAE4` / `#2A2822`): the **inset**. Everything that is recessed
  or "not yet raised": button rest fill, socket wells, type chips, keycaps, meter tracks,
  segmented-control tracks, value chips.

### Text

- **`--text-primary`** (`#1D1C18` / `#F1EFE8`): titles, values, anything you read to act.
- **`--text-secondary`** (`#5A5850` / `#ABA89C`): supporting copy, unselected segment
  labels, field labels.
- **`--text-muted`** (`#6C695F` / `#928E83`): the quietest legible text — socket labels,
  ruler marks, type chips, idle socket cores. It is deliberately **darker than the
  handoff's `#8F8C82`** so 9.5px mono still clears 4.5:1 on the inset.
- **`--text-on-accent`** (`#1D1C18` in **both** themes): see the Ink-For-Text Rule.

### Lines

Three, and they are not interchangeable:

- **`--border-subtle`** (`#E3E1DA` / `#33312A`) — the hairline. Card edges, dividers,
  separators, the topbar rule. This is the default.
- **`--border-strong`** (`#C8C5BB` / `#4B473D`) — an interactive outline: inputs,
  selects, textareas, key tiles, toggle tracks, the grip dots.
- **`--border-control`** (`#89867C` / `#807C6F`) — where a control boundary has no fill
  delta behind it to carry it. As a **resting** ring that is exactly five components:
  the port socket well, the knob dial, the slider thumb, the toggle knob and the key
  tile. As a **hover** deepening it is the four text fields (`Input`, `Select`,
  `Textarea`, `DeviceSelect`), whose rest border is `--border-strong`. That is the whole
  list; do not spend it anywhere else.

### Accent and state

`--accent-primary` `oklch(0.66 0.19 40)` / `oklch(0.72 0.19 40)` is the instrument's one
brand colour: the selection, the play button, the lit key, the playhead.
`--accent-secondary` is its **hover**, and in light it *lifts* to `oklch(0.71 0.19 40)`
rather than darkening — because the label on top is dark ink, a darker hover would push
the label toward the floor (the handoff's darker hover measured **3.98:1**).

`--accent-success` / `--accent-warning` / `--accent-danger` are machine state, as fills
and glyphs only.

### The ink pair

`--accent-ink`, `--success-ink`, `--warning-ink`, `--danger-ink`, `--audio-ink` are the
**text** partners of the five colours above. A state colour at full saturation is a fine
fill and a poor letterform; the ink is the same hue darkened (light) or lightened (dark)
until it clears 4.5:1 on both the card and the inset — including on its own 10% and 18%
tint washes, which is what a danger button is made of.

### Wiring — the legend

- **`--audio-connection` / `--audio-connected`** `oklch(0.6 0.12 200)` — **teal.**
  Everything that carries *sound*: audio socket cores, audio cables, note fills,
  waveform traces. (This replaced the old blue; if you see `#4A90C2`, it is stale.)
- **`--control-connection` / `--control-connected`** (`#8F8C82` / `#767267`) —
  everything that carries *numbers and triggers*. Deliberately desaturated so sound reads
  as the signal that matters.
- **`--universal-connection`** `oklch(0.66 0.19 300)` — ports that
  adapt to whatever they connect to. A flat violet: **the rainbow gradient is retired.**

### Timeline

Twenty `--timeline-*` tokens carry the arrangement so a theme can retune the DAW without
touching a component: lane and alternating-lane grounds, a three-level grid
(`bar` / `beat` / `sub` at 24% / 11% / 5.5% ink), clip ground and border, note and
waveform fills, the violet automation line, the accent playhead and selection, the loop
range wash, and the section marker.

Two of them are load-bearing decisions:

- **`--timeline-clip-border` is `--text-muted`, not a hairline.** A clip edge is a content
  boundary, so WCAG 1.4.11 applies; the hairline value measured **1.73:1** on a white
  lane. The shipped value measures **5.49:1 light / 5.05:1 dark**. On a projector, a
  hairline clip edge is invisible. Legible beats delicate.
- **`--timeline-grid-bar` at 24% is a rhythm floor, not a text floor** — the test holds it
  at ≥1.5:1 against the lane so the bar pulse survives a bad projector.

### Named Rules

**The Port-Color-Is-Meaning Rule.** Port and cable colour is never decoration. Teal means
audio, grey means control, violet means universal — the port's `type` is the source of
truth and the colour follows from it. A performer learns the whole wiring legend in
seconds. Do not spend these colours on anything that is not a port or a cable.

**The Signal-Not-Brand Rule.** Success / warning / danger report *machine state* and always
travel with a label or an icon. The accent is the brand and the selection. Never style a
heading, a surface, or a decorative element in a state colour — and never use
`--accent-success` to mean "selected" (green means *healthy*, not *chosen*).

**The Ink-For-Text Rule.** A saturated colour is a fill; its `*-ink` sibling is the text.
Fill with `--accent-danger`, write with `--danger-ink`. And in **both** themes
`--text-on-accent` is dark ink `#1D1C18`, not white: white on our accent measures
**3.36:1**, dark ink measures **5.08:1 light / 6.27:1 dark**. This is a deliberate,
documented deviation from the handoff, and it is why the light hover has to lift instead
of darken. If you ever find yourself writing `color: #fff` on an accent fill, the rule is
what you are breaking.

### Accessibility floors

The floors are not aspirational — `src/components/Arrangement/__tests__/contrast.test.ts`
reads the DTCG token files directly and asserts them for **both themes** on every run:
body text ≥ **4.5:1**, non-text boundaries and meaningful marks ≥ **3:1**, the bar-grid
rhythm ≥ **1.5:1**, `--text-on-accent` ≥ 4.5:1 against *both* `--accent-primary` and
`--accent-secondary`, each `*-ink` ≥ 4.5:1 on its own colour's 10% **and** 18% wash,
`--danger-ink` ≥ 4.5:1 on all four grounds, and `--border-control` ≥ 3:1 on the three
grounds it is allowed to sit on. The same test asserts that both themes declare the same
key set and that **no token key contains a digit** (the build's `camelToKebab` cannot
hyphenate before a digit — that is why depth is `shadowRaised`, not `sh1`).

| `--text-on-accent` on `--accent-primary` | 5.08 | 6.27 | 4.5 |
| `--danger-ink` on `--bg-tertiary` | 5.59 | 5.70 | 4.5 |
| Socket idle core (`--text-muted`) on the inset well | 4.57 | 4.50 | 4.5 |
| Socket well ring (`--border-control`) on the inset | 3.03 | 3.53 | 3 |
| `--border-strong` on `--bg-node` (rendered pixels) | 3.35 | 6.07 | 3 |
| `--timeline-clip-border` on the lane | 5.49 | 5.05 | 3 |
| Key tile — white-key / black-key legend | 17.05 / 5.49 | 14.23 / 4.99 | 4.5 |
| Lane button — mute / solo / armed / off | 6.14 / 6.43 / 6.72 / 4.57 | 8.03 / 6.60 / 6.28 / 4.50 | 4.5 |
| Command palette — every text run swept | ≥4.57 | ≥4.50 | 4.5 |

A full sweep of the node faceplates measured **61 text runs per theme, zero failures**,
worst case 4.57 / 4.50 — and 9.5px micro-mono is held to **4.5**, not the 3:1 large-text
exemption, because small mono is exactly where a bad ratio hurts.

**Known exceptions, all deliberate:**

- **Disabled controls** sit at ~1.85–2.17:1 (a 45–55% fade). WCAG 1.4.3 exempts disabled
  UI, and a disabled control that reads as enabled is the worse failure on stage.
- **The lane-button recording glyph** is 3.58:1 — a non-text mark, above the 3:1 bar, and
  it never travels alone (the button is also filled and pulsing).
- **Command-palette selection** separates by hue at 1.20:1 / 1.12:1 against the panel; the
  selection is *also* carried by `--accent-ink` on the label, so it is never colour-alone.

Beyond contrast, three floors are structural: **one focus ring** (`--focus-ring`, on
`:focus-visible` only — never on mouse focus, never a second ring vocabulary); **13px
minimum** for functional UI text; and **one blanket reduced-motion rule** (see §4).

## 3. Typography

**UI & titles:** Outfit (400 / 500 / 600 / 700), self-hosted woff2 — one face, every size,
including buttons, node titles, menus and headings.
**Exact values:** JetBrains Mono (with Fira Code fallback).

Two faces, two jobs. Outfit is a geometric sans with enough warmth to not feel like a
dashboard and enough discipline to disappear at 13px under stage light. Mono appears only
where digits and keys must be read, typed, or compared. There is no third face, and there
is **no display face** — the retired Caveat is not "kept for empty states."

### Hierarchy

Sizes are the primitive scale (`--text-*` in `packages/oj-tokens/tokens/primitive.json`):

| Role | Token | Face / weight | Where |
|---|---|---|---|
| **Display** | `--text-2xl` 30px | Outfit 700 | The onboarding question, Safe Mode. The only 30px on screen. |
| **Title** | `--text-xl` 22px | Outfit 600 | `PanelHeader` titles, panel and dialog headings. |
| **Node title** | `--text-lg` 15px | Outfit 600 | `NodeShell` titles, the transport position readout (mono). |
| **Body** | `--text-md` 14px | Outfit 500 | The default: buttons, menu items, inputs, list rows, toggle labels. |
| **Small** | `--text-sm` 13px | Outfit 500–600 | Segmented labels, callout body, scrubber labels. **The floor.** |
| **Mono** | `--text-xs` 11px | JetBrains Mono 500 | Keycaps, node type chips, knob label + value, latency chips. |
| **Micro** | `--text-micro` 9.5px | JetBrains Mono 600, `--tracking-micro` .08em, uppercase | Socket labels, ruler marks, unit labels. |

`Field` labels are the one 12px sans exception (600, uppercase, `.02em`) — they name a
control rather than carrying information, and they are held to the same 4.5:1 bar. It is
the ONLY one: a `Chip` carries information (a tag, a state, a count), so it sits on the
13px floor with everything else — §5 used to say 12px and §3 forbade it, and §3 won.

### Named Rules

**The Outfit-Is-the-Voice Rule.** One sans does everything, at every size, in both themes.
Weight and size carry hierarchy; a second face never does. If a surface needs "personality,"
it needs better spacing, not a different font.

**The Mono-Means-Exact Rule.** If a value is monospace, it can be read, typed, copied, or
compared character by character — a BPM, a dB reading, a key binding, a port name, a bar
position. Mono always carries `tabular-nums` where it shows a number. Never use mono for
emphasis or decoration, and never set an exact value in the sans.

**The 13px Floor.** No functional UI text below 13px in the sans. The two smaller steps
exist *only* for uppercase mono micro-labels (11px and 9.5px), where the letterforms are
wide, spaced (`--tracking-micro`), and held to the full 4.5:1 body-text bar rather than a
large-text exemption. If a label needs to be smaller than 13px and is not one of those,
the layout is wrong.

## 4. Elevation

The system is **soft, layered, low-alpha depth** — never a hard offset, never a glow. The
retired language drew a sticker shadow with zero blur; this one draws real light. Both
shadow roles are two stacked shadows: a tight contact shadow plus a wide ambient one.

### The four depth roles

| Token | Value (light) | Job |
|---|---|---|
| `--shadow-raised` | `0 1px 2px rgba(24,22,16,.05), 0 2px 6px rgba(24,22,16,.06)` | Something sitting *on* the ground: key tiles, the selected segment, callouts, banners, waveform cards, the knob dial. |
| `--shadow-overlay` | `0 2px 6px rgba(24,22,16,.07), 0 12px 28px rgba(24,22,16,.11)` | Something floating *above* it: node cards, menus, modals, popovers, the transport pill. |
| `--shadow-inset` | `inset 0 1px 3px rgba(0,0,0,.22)` | Something recessed *into* it: the socket well. |
| `--shadow-pressed` | `inset 0 2px 6px rgba(0,0,0,.28)` | Something being *hit right now*: a lit key tile. |

Dark theme swaps them for black-based equivalents at higher alpha — same four names, same
four jobs.

### The one focus ring

`--focus-ring` = `0 0 0 3px color-mix(in oklab, var(--accent-primary) 28%, transparent)`
(35% in dark). It appears on `:focus-visible` only, and it **stacks** rather than replaces:
a focused node reads `var(--shadow-overlay), var(--focus-ring)`; a focused socket reads
`var(--shadow-inset), var(--focus-ring)`. There is no second focus vocabulary. `ListRow`
is the one component that focuses with a 1.5px `outline` instead — it lives inside
scrollers with `overflow: hidden`, where a spread shadow gets clipped. (A 1.5px accent
`outline` is also how `WaveformView` draws *selection*, which is a different job.)

### Motion

Two curves, and each owns a property set:

- **`--motion-fast`** `120ms cubic-bezier(.2,.8,.3,1)` — colour, background, border,
  box-shadow. Fast enough to feel like a light turning on.
- **`--motion-spring`** `260ms cubic-bezier(.34,1.56,.64,1)` — **`transform` only.** The
  overshoot is the weight. Never spring a colour.

The physical vocabulary is three gestures and nothing else:

- **Press** → `scale(var(--press-scale-btn))` = `.96` for buttons,
  `scale(var(--press-scale-pad))` = `.94` for pads and keys. The box never moves.
- **Hover lift** → `translateY(var(--hover-lift))` = `-2px`, on pads and keys only.
- **Hit** → a lit key drops to `translateY(1px)` with `--shadow-pressed`; it is being
  held, not hovered.

**The blanket reduced-motion rule** lives once, in `src/styles/global.css`:

```css
@media (prefers-reduced-motion: reduce) {
    *:not(.oj-cable):not(.oj-meter):not(.oj-meter *), *::before, *::after {
        animation-duration: .01ms !important; animation-iteration-count: 1 !important;
        transition-duration: .01ms !important; scroll-behavior: auto !important;
    }
}
```

There are **exactly two exemptions**, `.oj-cable` and `.oj-meter` (and the meter's bars),
because those are not animations — they are **meters**, and a meter that stops reporting is
a lie. Everything that pulses for attention has a static alternative declared outside its
keyframe: the transport's attention ring becomes a static ring, a recording lane button
becomes a static `0 0 0 2px var(--danger-ink)`, a recording waveform keeps its danger
stroke at full opacity.

**The rule about component-level blocks, stated as it actually holds.** This section used
to say "no component ships its own `prefers-reduced-motion` block", and 13+ stylesheets
break that, so the sentence was simply false. The real rule — the one the code has been
following — is narrower and more useful:

> The blanket rule owns *turning motion off*. A component block may only **substitute a
> static equivalent** for something whose meaning the clamp would destroy: an animation
> replaced by the frame it should rest on (`.arrangement-arm.is-recording` keeps a
> `box-shadow` ring where its pulse was), a `transform` replaced by a fixed one, a colour
> swapped for a stronger one. It may never **re-add** a transition or an animation.

That last clause is not hypothetical: `Slider.css` re-declared
`transition: box-shadow var(--motion-fast)` inside a `reduce` block — the one rule in the
app that handed motion back under the preference. It is now `none`, and both halves of the
rule (no empty blocks, no re-added durations) are gated by
`src/components/__tests__/reducedMotionContract.test.ts`.

### Named Rules

**The Nothing-Glows-Except-Live-Signal Rule.** `filter: drop-shadow(...)` and soft coloured
halos exist in exactly one place in the library: `Cable`, driven by the real signal level.
Meters brighten and clip-latch. **Ports never glow** — not on hover, not on connect, not
when active. Neither do buttons, selections, node borders, or anything else. If it glows
and it is not carrying audio right now, it is a bug.

**The Press-Has-Weight Rule.** A control answers the hand within 120ms and *compresses*:
scale down on press, spring back on release, on the one spring curve. Weight is scale and
shadow, never a jump in position.

**The No-Surprise Rule.** A control never moves, resizes, or reflows under the cursor.
Hover feedback is colour, border and — on pads only — a 2px lift. On a performance
surface, a control that jumps is a control that gets mis-clicked. Corollary: a hit target
never oscillates (the transport's attention pulse is a ring *behind* a button whose box is
fixed).

**The One-Ring Rule.** Focus is `--focus-ring` on `:focus-visible`, stacked over whatever
shadow the element already has. Not an outline, not a colour change alone, not a second
ring style for "important" controls.

## 5. Components

Every class name below is the real one; every value is measured from
`packages/oj-ui/src/components/`. The library is **44 folders → 60 exported React
components** (48 named + 12 icons).

### The Node — the signature component

`NodeShell` → `.oj-node`.

- **Card:** `--bg-node`, **1px** `--border-subtle`, `--radius-lg` (14px),
  `--shadow-overlay`, `min-width: var(--node-min-width)` (190px).
- **Header** (`.oj-node__header`): `--bg-node-header`, `10px 14px`, closed by one
  `--border-subtle` hairline, `cursor: grab` → `grabbing`. It holds three things, always in
  this order:
  - **The grip** (`.oj-node__grip`): four 3×3px dots in a 2×2 grid at 2.5px gap, in
    `--border-strong`. It says "this whole card moves" without a word.
  - **The title** (`.oj-node__title`): Outfit 600 / 15px.
  - **The type chip** (`.oj-node__type`), right-aligned: mono 500 / 11px, uppercase,
    `--tracking-micro`, `--text-muted` on `--bg-tertiary`, `--radius-sm`, `4px 7px`.
- **Body:** `12px 14px`, `gap: 12px`. The **first row is always the ports**
  (`.oj-node__ports`): inputs left, outputs right (`margin-left: auto`).
- **States:**
  - `.is-selected` — `border-color: var(--accent-primary)` plus
    `inset 0 0 0 0.5px var(--accent-primary)`, an optical 1.5px edge that changes no
    dimension. **Selection is an edge, never a fill wash.**
  - `:focus-visible` — `var(--shadow-overlay), var(--focus-ring)`; selected + focused
    stacks all three.
  - `.is-dragging` — `opacity: .96` plus a wide 18px/40px ambient drop; the card lifts, it
    does not tilt.
  - `.is-agent-pending` — a 1.6s breathing ring in `--universal-connection`. The agent's
    pending work is the *only* thing that borrows the universal violet outside a port.
  - `.is-bypassed` — `--bg-tertiary`, struck-through title, a hairline strike across the
    body. `.is-watchdog-bypassed` adds a `--accent-warning` inset edge: the engine did
    this, not you.
- **Going deeper:** a node can be used as-is or opened (press `E`) to reveal and rewire its
  internal graph. The card language is identical at every depth, so depth never feels like
  a different app.

### Ports and cables

`Port` → `.oj-port`, `PortRow` → `.oj-port-row`.

- **The socket well:** `var(--port-size)` = **18px** circle, `--bg-tertiary` fill, **1px**
  `--border-control` ring, `--shadow-inset`, `cursor: crosshair`. Inside it, an **8×8px
  core dot** (`::after`), `--text-muted` when idle.
- **Connected** repaints the core only — `--audio-connection` / `--control-connection` /
  `--universal-connection`. Idle sockets of every kind read identically, which is the
  point: the colour appears when there is something to say.
- **Hover** is `border-color: var(--accent-primary)`. **No scale. No glow.**
  **Focus-visible** is `var(--shadow-inset), var(--focus-ring)`.
- `.is-placeholder` — dashed ring, no fill, no core, `cursor: copy` ("a cable could go
  here"). `.is-active` — core turns `--success-ink`; no pulse, no halo.
- **The row** (`.oj-port-row`): 24px min-height, 7px gap, socket + label. Inputs are
  `[socket][label]` left-aligned; outputs are `[label][socket]` right-aligned. Labels are
  micro mono: 9.5px / 600 / uppercase / `--tracking-micro` / `--text-muted`, brightening to
  `--text-secondary` when connected.
- `data-node-id` / `data-port-id` / `data-port-type` stay on `.oj-port` — the canvas
  connection math resolves against the DOM, so never strip them.

`Cable` → `.oj-cable`. **The one thing allowed to glow**, and only in proportion to the
signal actually flowing. The app feeds the live level in as `--oj-cable-signal` (0–1,
`signalLevel` clamped and written onto the path); the CSS does the rest:

```css
stroke-width: calc(2.5px + var(--oj-cable-signal) * 2.5px);
opacity:      calc(0.5 + var(--oj-cable-signal) * 0.5);
filter:       drop-shadow(0 0 calc(var(--oj-cable-signal) * 7px) currentColor);
```

At rest `.is-quiet` pins it to 2.5px at 45% with `filter: none`. Selected adds 1px,
bundled adds 2px; a temporary drag cable is dashed and marching. The hit path is a
separate transparent 14px stroke — a cable is easy to grab and impossible to mistake for
chrome.

### Controls

- **Button** (`.oj-btn`) — flat inset construction: `--bg-tertiary`, `9px 16px`,
  `--radius-md`, **no border, no shadow at rest**, Outfit 600 / 14px. Hover mixes 8%
  `--text-primary` into the fill; press is `scale(.96)`; focus is the ring.
  `--primary` fills `--accent-primary` with `--text-on-accent` and hovers to
  `--accent-secondary`. `--danger` / `--success` are a **10% wash of the state colour on
  the inset with the matching ink as text** (18% on hover) — a tinted button, never a
  saturated slab. `--ghost` is transparent → inset. `--link` is `--accent-ink` with an
  underline on hover and no press scale. `--icon-only` is 34×34. Loading hides the label
  but keeps the box, so nothing reflows.
- **Knob** (`.oj-knob`) — the standard faceplate control. 52px
  (`--knob-size`), `radial-gradient(circle at 35% 30%, var(--bg-node), var(--bg-tertiary))`,
  1px `--border-control`, `--shadow-raised`. A 3px `--accent-primary` tick sweeps
  **−135° … +135°** and has **no transition** — it must track the finger exactly. Hover,
  focus and drag all add the focus ring rather than inventing a state colour. It is a real
  `role="slider"`: ↑/→ ±1 step, ↓/← ∓1, PageUp/Down ±10, Home/End to the ends; vertical
  drag over 150px is a full sweep, `Shift` for 0.1×, double-click resets. Label and value
  sit below in 11px mono.
- **Slider** (`.oj-slider`) — 6px pill track, `--accent-primary` fill; 18px `--bg-node`
  thumb with a **1.5px `--border-control`** ring and `--shadow-raised`. Hover scales the
  thumb 1.15× and adds the ring.
- **Toggle** (`.oj-toggle`) — 40×23 pill track, 17px knob travelling 17px on
  `--motion-spring`. Checked fills the track `--accent-primary` and drops the border.
- **SegmentedControl / Tabs** (`.oj-seg`) — a 3px-padded `--bg-tertiary` track; the
  selected segment is a **raised `--bg-node` card with `--shadow-raised`**, not an accent
  fill. Labels 13px / 600.
- **Input / Select / Textarea** (`.oj-input`, `.oj-select`, `.oj-textarea`) — `--bg-node`,
  1px `--border-strong`, `--radius-md`, `9px 12px`. Hover deepens to `--border-control`;
  focus is `--accent-primary` border **plus** the ring; `aria-invalid` swaps both for
  `--danger-ink` and a danger ring. `.oj-input--mono` for exact values.
  **Field** (`.oj-field`) puts a 12px/600 uppercase `--text-secondary` label above and the
  description/error below the control, so an error never pushes the control down the page.
- **ValueScrubber** (`.oj-value-scrubber`) — a 12px mono value on a `--bg-tertiary` chip,
  `cursor: ew-resize`. Hover draws a 1px **inner** outline (`inset 0 0 0 1px`) so nothing
  moves. **ParamRow** wraps a label + value chip + control; a value under automation gets a
  1px `--timeline-automation-line` underline (`inset 0 -1px 0`) — a hairline, never a glow.
- **KeyTile** (`.oj-key-tile`) — the playable surface. 48px, `--radius-md`, `--bg-node`,
  1px `--border-control`, `--shadow-raised`, a bottom-anchored 10px mono legend, and its
  own control-`Port` socket inset in the top-right corner. Rest → hover `translateY(-2px)`
  → press `scale(.94)` → **held**: solid `--accent-primary`, `--text-on-accent` legend,
  `translateY(1px)` and `--shadow-pressed`. A held key looks pressed *into* the instrument.
  Variants: `--pad` (square), `--key` (34×74), `--white` (34×96), `--black` (24×64).

### Surfaces and feedback

- **Surface** (`.oj-surface`) is the shared ground: `--bg-node`, 1px `--border-subtle`, and
  one of two elevations. Menu, Modal, Callout and Banner are all built on it, which is why
  they cannot drift apart.
- **Menu** (`.oj-menu`) — overlay surface, 12px radius, 6px padding; items 14px/500 at
  `8px 10px` with an 8px radius, hover and focus both `--bg-tertiary`. Shortcuts render as
  `Kbd` keycaps; category headers are the **Micro voice** (`--text-micro` 9.5px JetBrains
  Mono 600, `--tracking-micro`, uppercase, `--text-muted`) — they name a group rather than
  carrying information, so they change FACE to stay quieter than the 14px items above them
  instead of dropping below the 13px sans floor, which §3 forbids; separators are a
  1px `--border-subtle` line inset 8px. There is **one** menu vocabulary — the canvas
  context menu, the File/Edit/View menus and every dropdown are this component.
- **Modal** (`.oj-modal`) — `--overlay-scrim` with a guarded 14px backdrop blur, an
  `--radius-xl` (20px) overlay card, and a 14px spring rise. Reduced motion *or* reduced
  transparency removes both the blur and the animation.
- **Callout / Banner** — a surface card with a hairline and `--shadow-raised`. The variant
  tints **the title and the icon only** (via `--callout-accent` / `--banner-accent`, always
  an ink token); the body stays `--text-secondary`. **There is no left accent bar and no
  tinted body wash.**
- **Chip** (`.oj-chip`) — a pill on the inset, **13px/600** (`--text-sm`; the trailing
  `count` slot stays 11px mono), tones recolouring the **text**
  only. **No dot inside a chip** — the component actively strips a `●`-style glyph or a
  nested `StatusDot`. Pressed lifts to `--bg-node` + `--shadow-raised`.
- **StatusDot** — an 8px pill, borderless, ink-coloured by status. It stands alone next to
  a label; it never lives inside a chip.
- **Kbd** (`.oj-kbd`) — an 11px mono keycap on the inset with a hairline and a 5px radius.
  `--custom` recolours it `--accent-ink` when the binding has been remapped, so a rebound
  key is never advertised wrong.
- **ListRow** (`.oj-list-row`) — hover `--bg-tertiary`; selected is `--bg-tertiary` with an
  `--accent-ink` label; the current item takes a 6px `--accent-ink` dot before its body.
- **ProgressBar / Spinner** — a 6px pill track with a **solid** fill (never a gradient);
  the spinner is a 1px ring with an `--accent-primary` top edge. Under reduced motion the
  bar goes full-width at 40% and the spinner simply stops, still readable.
- **PanelHeader** — a 22px/600 title over a `--border-subtle` rule, with optional
  back/close Buttons, a badge and an actions slot. Every panel in the app wears it.

### The Timeline

The arrangement and piano roll are one document surface with a sticky ruler and sticky
track headers inside a single scroller. The visual grammar:

- **Chrome** (`--timeline-chrome-bg`) for the ruler and the header column; alternating
  lanes (`--timeline-lane-bg` / `--timeline-lane-alt-bg`) so the eye can track a row across
  16 bars.
- **A three-level grid** — bar / beat / sub at 24% / 11% / 5.5% ink. The bar line is the
  only one you should notice at a glance.
- **Clips** are cards: `--timeline-clip-bg`, a `--timeline-clip-border` edge, with the
  **track's colour identity** as a left edge. This is the *only* sanctioned side stripe in
  the system, and it exists because a track colour is data.
- **Notes** in `--timeline-note-fill` (teal — the same "this is sound" as a cable),
  waveforms in `--timeline-waveform-fill`, automation in violet
  (`--timeline-automation-line`), the playhead and selection in accent.
- **`Meter`, `TimeRuler` and `LaneButton`** are oj-ui components, so a track header's
  M / S / ● reads exactly like the rest of the instrument.

The gestures, keys, snap behaviour and editing contracts are **[docs/timeline.md](docs/timeline.md)** —
do not restate them here.

### The Shell

- **Topbar** — a 46px `--bg-node-header` band closed by one hairline: left = where you
  are (brand, File/Edit/View, breadcrumbs), centre = which surface (a segmented control),
  right = how things are (undo/redo, engine dot, latency chip, project/offline chips,
  collab, theme, settings). Chrome, and it behaves like chrome: it releases focus after a
  pointer activation and keeps it after a keyboard one.
- **One transport pill** (`.oj-transport`) — 44px, `--radius-pill`, `--bg-node`,
  `--shadow-overlay`, floating top-centre and **identical on every surface**. Zones are
  separated by hairlines, not gaps, and a zone appears only when it is *true* for the
  current document. The play button is a 32px accent circle; the meter is six
  `--accent-success` bars that turn `--accent-danger` and latch on clip.
- **The meter and the position readout never re-render.** They are written straight onto
  the DOM from one shared animation frame via `--oj-meter-signal`. A rolling transport
  costs zero React renders.
- **First run** is three questions over the **real studio**, blurred 5px and
  non-interactive — a sneak peek, not a picture. Full-screen moments (onboarding, Safe
  Mode) share one card language: brand row, 30px question, big option cards with mini
  component glyphs.

Both are documented in full in **[docs/shell.md](docs/shell.md)**.

## 6. Do's and Don'ts

### Do

- **Do** keep the ground calm and spend colour on signal, state and selection only.
- **Do** use the four depth roles — raised / overlay / inset / pressed — and let them mean
  what they say: on it, above it, into it, being hit.
- **Do** give every control weight: `--motion-fast` for colour, `--motion-spring` for
  transform, press `.96` (buttons) or `.94` (pads), hover lift −2px on pads and keys.
- **Do** let live audio be the only thing that lights up — cables scale with
  `--oj-cable-signal`, meters with `--oj-meter-signal`.
- **Do** colour ports and cables strictly by type: audio = teal, control = grey,
  universal = violet.
- **Do** fill with a state colour and write with its `*-ink` sibling.
- **Do** use one focus ring, on `:focus-visible`, stacked over the element's own shadow.
- **Do** put exact values in JetBrains Mono with `tabular-nums`, and keep functional sans
  text at 13px or larger.
- **Do** be honest about state — a transport glyph that waits for the engine, an honest
  `~15–25ms` browser tier, a failure that never hides behind a hopeful spinner.
- **Do** prefer a held, believable sound over a visible glitch when something fails
  mid-set, and report it without stealing focus (the Live Performance Rule).
- **Do** keep every value in a token, so the community can reskin the instrument — a
  high-contrast, larger-type, or colour-blind-safe theme — without forking a component.

### Don't

- **Don't** put a **glow on a port** — not on hover, not on connect, not when active. Nor
  on a button, a selection, a node border, or anything else that is not carrying audio
  right now.
- **Don't** draw a **side stripe**. The only sanctioned left edge in the system is a
  timeline clip's track-colour identity, because that stripe is data. Callouts, banners,
  list rows, menu items and panels get none.
- **Don't** put a **dot inside a chip**. A chip's tone recolours its text; `StatusDot`
  stands beside a label, never inside a pill.
- **Don't** express selection as a **fill drench**. Selection is an accent edge (plus, at
  most, an inset ring or an ink label). A saturated wash over a card destroys the contrast
  of everything on it.
- **Don't** use a **display font in functional UI**. There is one sans and one mono.
  Caveat is retired and is not coming back for empty states.
- **Don't** write a **hard offset shadow** (`2px 3px 0 …`). Depth is soft and layered.
  Zero-blur offsets are the retired language.
- **Don't** draw a **2px ink border**. Borders are 1px hairlines; 1.5px is the maximum, and
  only on an interactive outline.
- **Don't** use `#fff` (or any literal) on an accent fill — `--text-on-accent` is dark ink
  in both themes for a measured reason.
- **Don't** style a heading, a surface, or a decoration in a **state colour**, and don't
  use `--accent-success` to mean "selected."
- **Don't** re-add a transition or an animation inside a `prefers-reduced-motion: reduce`
  block. The blanket rule in `global.css` owns turning motion OFF (with exactly two
  exemptions); a component block may only substitute a static equivalent for meaning the
  clamp would destroy — never hand a duration back.
- **Don't** let a control move, resize, or reflow on hover or press.
- **Don't** ever present a wall — no "pro" ceiling, no dead end. The instrument is
  infinitely deep, and it should look like it at every depth.
