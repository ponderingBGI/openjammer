Latency is the one thing your fingers feel before your eyes read anything. OpenJammer ships
sensible defaults that work immediately, but a USB audio interface plus a few settings will
get you from "good enough to sketch" to "the software disappears and only the music is left."

## The honest latency tiers

There is no single latency number — it depends on whether you run native or in the browser,
and on your hardware:

| Where you run | Typical latency | Notes |
|---|---|---|
| **Native desktop** | **device-dependent: ~1.3 ms to ~10 ms+** | The lowest tier. The engine asks for a small 64-frame buffer (~1.3 ms); many devices grant it even in WASAPI shared mode, some fall back to a larger device period (~10 ms+). |
| **Native desktop** | **guaranteed low** with WASAPI-exclusive / ASIO | An exclusive/ASIO driver locks in the small buffer on any device — not yet routed by default. |
| Browser, built-in audio | 30–80 ms | Fine to try it out, high for tight playing. |
| Browser, USB interface | 10–20 ms | A USB interface is the single biggest browser improvement. |
| Browser, USB optimized | 3–10 ms | With Low Latency Mode + interactive hint + the right devices selected. |

We never label the browser tier sub-5 ms — and we don't over-promise one fixed native figure
either, because native latency is **device-dependent**. The engine asks the audio device for a
small **64-frame buffer (~1.3 ms)**. Many devices grant it **even in WASAPI shared mode** — on a
Windows test machine we measured ~1.3 ms (`Fixed(64)` @ 48 kHz), genuinely **sub-5 ms**, with no
exclusive/ASIO driver — while some devices or drivers reject the small buffer and fall back to the
device period (**~10 ms+**). A **WASAPI-exclusive or ASIO** driver (not yet routed by default)
*guarantees* the low buffer on any device. The browser stays honest at **~15–25 ms** out of the
box and is great for sketching and jamming.

## Tune the audio settings

Open **Settings** (the gear icon) → **Audio** tab. Three settings do most of the work:

1. **Low Latency Mode** — *Enable.* This disables echo cancellation and other input
   processing for a 20–50 ms improvement. It is safe with a USB interface in a quiet room
   (see the headphones note below).
2. **Sample Rate** — OpenJammer detects the running device rate when audio starts and
   sets this automatically when the platform reports it. **48 kHz** is a good manual
   target; choose 96 kHz only if your interface supports it and you need it.
3. **Latency Mode** — **Interactive** for the lowest latency. Drop to **Balanced** if you
   hear crackle.

You can see your **actual measured latency** in the Audio Settings panel, and the AI
assistant (Ctrl/Cmd+K) can read it and change these settings for you reversibly — see
[Troubleshooting with the AI](/openjammer/play/troubleshooting-with-the-ai/).

For the best jamming experience, use a USB audio interface instead of built-in audio. These
all work class-compliant (no drivers needed) unless noted:

converters, and class-compliant USB that works without drivers on every platform.

## Set up your interface

1. **Connect it.** Most interfaces work over a standard USB 2.0/3.0 or USB-C port, and most
   are bus-powered (no external power needed).
2. **Grant permissions** (browser). Click **Start OpenJammer**, grant microphone access when
   asked, then open **Settings → Audio** and select your interface from the device dropdown.
3. **Enable the optimizations** above (Low Latency Mode, the detected sample rate or 48 kHz, Interactive).

**Expected result:** built-in audio is 30–80 ms; a basic USB interface is 10–20 ms; an
optimized USB interface is 3–10 ms.

## Why the browser can't use ASIO

Web browsers **cannot access ASIO drivers**. They use the OS audio layer instead:

- **Windows** — WASAPI (10–30 ms typical)
- **macOS** — Core Audio (3–5 ms typical)
- **Linux** — ALSA / JACK (varies by configuration)

This is a browser limitation, not an OpenJammer one. A USB interface still helps a lot in the
browser — better hardware buffering and low-latency-optimized drivers — but for the lowest,
most consistent latency use the [native desktop app](/openjammer/play/install/): it asks the
device directly for a small 64-frame buffer (~1.3 ms), which many devices grant even in WASAPI
shared mode, and a future WASAPI-exclusive or ASIO path will lock that buffer in on any device.

## OS-specific notes

- **macOS** — generally the best latency, thanks to Core Audio. Most interfaces are
  class-compliant (no drivers).
- **Windows** — native latency is device-dependent: the engine requests a small 64-frame
  buffer, which many devices grant even in WASAPI shared mode, while others fall back to a
  larger device period. A USB interface helps significantly. Some interfaces need manufacturer
  drivers — check the support page. Enabling exclusive mode in Windows Sound settings can lock
  in the small buffer on a device that otherwise refuses it.
- **Linux** — setup varies by distro. JACK gives the best latency but needs configuration;
  PipeWire offers a good balance; PulseAudio works but is higher latency.

## Verify your setup

In Audio Settings, confirm:

- ✅ Your USB interface is detected (a banner appears).
- ✅ Total latency is under ~15 ms (excellent).
- ✅ Low Latency Mode is enabled (if you're in a quiet room).
- ✅ The correct input and output devices are selected.
