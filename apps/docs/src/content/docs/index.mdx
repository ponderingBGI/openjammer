OpenJammer is a **dual-target** audio app: the *same* Rust engine (`ojcore`) runs
both as a native Tauri desktop app on a small-buffer audio stream, and compiled to
`wasm32` inside a browser AudioWorklet. You build a signal graph on a canvas and
perform with it live.

<CardGrid stagger>
  <Card title="Hard real-time" icon="rocket">
    The audio thread never allocates, locks, or blocks — a guarantee enforced
    mechanically in CI. See [Real-time safety](/openjammer/architecture/real-time-safety/).
  </Card>
  <Card title="Everything on device" icon="laptop">
    Structured logs stream to an on-device rolling file and a searchable in-app
    panel — never to a server. See [Logging &amp; observability](/openjammer/architecture/logging/).
  </Card>
  <Card title="One wire schema" icon="setting">
    A single `ojproto` event/IR schema crosses the native ↔ browser seam,
    parity-gated against its TypeScript mirror.
  </Card>
  <Card title="Report a problem" icon="comment">
    A one-click reporter bundles a redacted diagnostic snapshot + log tail into a
    pre-filled GitHub issue — secrets and home paths auto-scrubbed.
  </Card>
</CardGrid>

:::note
These docs are a living reference for contributors. Engine internals are
documented inline in the Rust crates (`cargo doc`); this site covers the
cross-cutting architecture, the release/version model, and how to contribute.
:::
