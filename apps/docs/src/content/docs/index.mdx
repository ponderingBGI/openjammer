## Two ways in

<CardGrid>
  <Card title="Play" icon="open-book">
    Open the canvas, drop a keyboard and a synth, draw a cable between them, and you are
    making sound. Native desktop gives you low latency — it asks the device for a small 64-frame
    buffer (~1.3 ms), which many devices grant even in WASAPI shared mode, down to ~10 ms+ on
    devices that force a larger period; the browser tier is an honest **~15-25ms** —
    fast enough to jam, no install required.

    [Start playing →](https://openjammer.app)
  </Card>
  <Card title="Build" icon="setting">
    A deliberately tiny Rust core (`ojcore`) turns a graph into sound and blocks for
    nothing. *Everything else* — instruments, effects, AI-authored DSP — is a plugin
    behind one `DspInstance` contract. Extend the edges; never fork the core.

    [Read the architecture →](/openjammer/build/architecture/real-time-safety/)
  </Card>
</CardGrid>

:::tip[A held note beats a glitch]
The audio thread never allocates, locks, or blocks — enforced mechanically in CI. When
something breaks mid-set, OpenJammer preserves the last good sound and reports without
stealing your focus. Latency is not a number here; it is the threshold below which the
software disappears and only the music is left.
:::
